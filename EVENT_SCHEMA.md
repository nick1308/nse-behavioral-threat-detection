# Event Schema

Defines the normalized event contract accepted by the scoring API. A broker
integration must map its own event format to this contract; the current demo
source is synthetic and is not a live broker connection.

## Core event fields

| Field | Type | Notes |
|---|---|---|
| `event_id` | string | Unique per event; may use the broker's ID or a generated UUID |
| `account_id` | string | The account this event belongs to |
| `timestamp` | ISO 8601 datetime | When the event occurred |
| `event_type` | enum | One of the types below |
| `device_id` | string or null | Pseudonymous device identifier when the broker is authorized to provide one; nullable because some sources do not expose it |
| `ip_address` | string or null | Network-origin identifier when available and approved; nullable and should be minimized/pseudonymized where appropriate |
| `session_id` | string | Groups events within one login session |

## Supported event types and type-specific fields

### LOGIN
| Field | Type |
|---|---|
| `success` | bool |
| `auth_method` | enum: `password`, `token`, `mfa` |

### LOGOUT
_(no extra fields — common fields only)_

### VIEW_STOCK
| Field | Type |
|---|---|
| `symbol` | string |

### ORDER
| Field | Type |
|---|---|
| `symbol` | string |
| `order_type` | enum: `buy`, `sell` |
| `quantity` | int |
| `price` | decimal |
| `order_value` | decimal (`quantity * price`, stored directly for fast feature computation) |

### CANCEL_ORDER
| Field | Type |
|---|---|
| `original_order_id` | UUID (references the ORDER event) |
| `time_since_order_ms` | int |

### API_REQUEST
| Field | Type |
|---|---|
| `endpoint` | string |
| `method` | enum: `GET`, `POST`, `PUT`, `DELETE` |
| `status_code` | int |
| `client_id` | string (for API-client-level baselining, separate from account_id) |

### TOKEN_REFRESH
| Field | Type |
|---|---|
| `token_type` | enum: `access`, `refresh` |

### PASSWORD_CHANGE
| Field | Type |
|---|---|
| `initiated_by` | enum: `user`, `admin_reset` |

### DEVICE_CHANGE
| Field | Type |
|---|---|
| `previous_device_id` | string |
| `new_device_id` | string |

The API validates the event type and rejects undeclared fields. Type-specific
attributes are optional in the transport model because adapters may have
partial telemetry; each detector must treat missing signals as unavailable,
not as proof of normal or malicious behavior.

## Ground-truth labeling (synthetic data only)

Every event generated by the synthetic data generator additionally carries:

| Field | Type | Notes |
|---|---|---|
| `is_attack` | bool | Ground truth — never exposed to the detection pipeline, only to the evaluation harness |
| `attack_type` | enum or null: `account_takeover`, `api_abuse`, `automated_trading`, `none` | Used to compute per-attack-type recall |

## Design notes

- `account_id` and `client_id` are tracked separately — account-level behavior (a human trader) and API-client-level behavior (a program hitting the API) get their own baselines, since their "normal" looks completely different.
- `order_value` is denormalized (computed at write time) rather than computed on read, because the feature-extraction layer needs it constantly and recomputing `quantity * price` per query is wasted work at real-time scale.
- Every event is immutable once written — corrections happen via new events (e.g. a cancel is its own event referencing the original order), never by editing history. This keeps the audit trail honest, which matters for a security project specifically.
